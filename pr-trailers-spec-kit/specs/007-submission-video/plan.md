# Plan · 007 — Submission video, rehearsal and submit

## Technical context
- Reuse the trailer template's styles (`templates/trailer/styles.css`) for visual consistency.
- Assets: `.trailer/1/trailer.mp4`, a screenshot of the PR comment (Playwright on the PR URL, or a manual screenshot), the pipeline diagram (HTML/CSS inside the composition).
- Use HyperFrames' built-in caption components for the on-screen captions.

## Approach
1. **Composition** `video/submission/index.html` (1920×1080 or 1280×720), about 90 s:
   | # | Scene | Duration | Content |
   |---|---|---|---|
   | 1 | Hook | 4 s | "You approved a PR you never saw." |
   | 2 | Problem | 10 s | Wall of diff lines scrolling; "AI writes more PRs than humans can check" |
   | 3 | Solution | 5 s | Logo / title "PR Trailers", tagline |
   | 4 | How it works | 12 s | Animated pipeline: PR → capture → Gemini → HyperFrames → comment |
   | 5 | The real trailer | 30–35 s | Embedded `trailer.mp4`, with a label: "Generated by PR Trailers for PR #1. Not edited." |
   | 6 | In the PR | 6 s | PR comment screenshot with the GIF, zooming in on the risks list |
   | 7 | Built with | 5 s | Gemini (vision narration), HyperFrames (every frame of this video), Playwright |
   | 8 | Outro | 5 s | Tagline, repo URL |
2. Render with the HyperFrames CLI → `video/submission/out.mp4`.
3. **Live demo script (3 min)**:
   - 0:00 Hook + problem (20 s, no slides; show PR #1's diff on GitHub).
   - 0:20 Run `npm run trailer -- 1 --force` in a large-font terminal and narrate the stages.
   - ~1:30 Refresh the PR → the GIF plays; open the MP4 full screen.
   - 2:20 Point at the risk: "the diff looked fine; the trailer caught the mobile break."
   - 2:40 Close with the tagline and mention Gemini + HyperFrames.
   - Backup: if the live run fails, play the recorded run or the cached trailer (Art. III).
4. **Submit**: repo public, README (pitch, GIF, how to run), video uploaded, categories selected.

## Constitution alignment
